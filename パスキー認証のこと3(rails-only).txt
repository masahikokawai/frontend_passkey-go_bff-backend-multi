共通する前提:どちらも、パスキーを登録するには、まず Keycloak(OIDC)でログインしている必要がある
ログイン時には backend の POST /internal/v1/users/provision(JIT プロビジョニング)が呼ばれ、users と user_keycloaks に行が作られる
セッションには、その user_id と Keycloak の access token(有効期限5分) が入る

場所: Rails

────────────────────────────────────────
順: ④
場所: Rails

  challenge に保存した user_id と、今のセッションの user_id が一致するかを確認する(不一致なら 401 invalid_state)
  WebAuthn::Credential.from_create(...).verify(challenge) で、challenge、origin(:5174)、rp_id、署名、attestation を検証
  失敗したら 422 verification_failed
保存先: ―
────────────────────────────────────────
順: ⑤
場所: Rails → backend
エンドポイントとコード: BackendClient#register_passkey! → POST /internal/v1/auth/webauthn/credentials

  body は credential_id、public_key(COSE を base64)、sign_count(BinData を .to_i で数値にする)
  backup_eligible(credential_backup_eligible?)、backup_state(credential_backed_up?)、transports、name
保存先: ―
────────────────────────────────────────
順: ⑥
場所: backend → MySQL
エンドポイントとコード: WebauthnHandler#Register
処理の詳細: JWT の iss が Keycloak なので、sub から user_keycloaks を引いて user_id を決める
  バイト列に戻して INSERT する
保存先: webauthn_credentials に1行(user_id、credential_id、public_key、sign_count、backup_eligible/backup_state が正しい値、transports、name)

## 3. ② bff-rails + with-bff:登録の流れ

```text

 │ POST :8102/api/auth/passkey/register/finish {state, credential} ─►│               │                                 │                  │
```

## 5. データの保存先の比較
一時データとセッション

